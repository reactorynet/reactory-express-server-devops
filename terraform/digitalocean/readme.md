# Reactory on DigitalOcean

Three tiers on DigitalOcean Kubernetes, sharing the same modules and the same
application contract as the AWS and Linode blueprints.

DigitalOcean offers managed engines for the entire Reactory stack — `pg`,
`mongodb`, `valkey` and `opensearch` — so unlike Linode the large tier needs
nothing self-hosted. **If you want a production deployment outside AWS, this is
the one to use.**

## Tiers

| | small | medium | large |
|---|---|---|---|
| Nodes | 1 × s-2vcpu-4gb | 2 × s-2vcpu-4gb | 3-8 × s-4vcpu-8gb, autoscaling |
| Control plane HA | no | no | yes (paid add-on) |
| PostgreSQL | pod | Managed, 1 node | Managed, 2 nodes |
| MongoDB | pod | pod | Managed, 2 nodes |
| Valkey | pod | Managed | Managed |
| Search | Meilisearch pod | Meilisearch pod | Managed OpenSearch |
| HPA / PDB | off | on | on |
| Ingress replicas | 1 | 2 | 3 |
| TLS | optional | optional | on by default, production ACME |
| VPC CIDR | 10.10.0.0/16 | 10.11.0.0/16 | 10.12.0.0/16 |

The tiers escalate on a deliberate principle. **small** is the cheapest thing
that is still a real cluster — everything in-cluster, disposable. **medium**
moves the two services whose managed behaviour differs most from a pod
(PostgreSQL and Valkey both enforce TLS and hand out generated credentials), so
QA exercises connection behaviour the small tier hides. **large** moves the rest
and adds redundancy.

Note the control plane HA is a **paid add-on** on DigitalOcean, roughly $40/month
on top of the nodes — unlike EKS, where it is implicit in the cluster fee.

## Getting started

### 1. Bootstrap (once per account)

```bash
cd digitalocean/bootstrap
cp terraform.tfvars.example terraform.tfvars   # set a globally unique bucket name
export DIGITALOCEAN_TOKEN="dop_v1_..."
export SPACES_ACCESS_KEY_ID="..." SPACES_SECRET_ACCESS_KEY="..."
terraform init && terraform apply
```

The API token and the Spaces keys are different credentials and are not
interchangeable — the token manages resources, the Spaces keys authenticate the
S3-compatible state backend.

```bash
export TF_STATE_BUCKET=$(terraform output -raw state_bucket_name)
export TF_STATE_ENDPOINT=$(terraform output -raw state_endpoint)
export AWS_ACCESS_KEY_ID="$SPACES_ACCESS_KEY_ID"
export AWS_SECRET_ACCESS_KEY="$SPACES_SECRET_ACCESS_KEY"
```

**Spaces has no state locking backend.** Concurrent applies against the same
tier will corrupt state. Coordinate, or apply only from CI.

### 2. Apply a tier

```bash
bin/terraform.sh apply --target=digitalocean/small/cluster  --reactory-env=dev
bin/terraform.sh apply --target=digitalocean/small/workload --reactory-env=dev --image-tag=1.1.0
```

`doctl` must be on PATH — the kubernetes provider authenticates through
`doctl kubernetes cluster kubeconfig exec-credential`, because the token in the
cluster resource's `kube_config` expires after about a week and would otherwise
produce a configuration that silently stops working.

### 3. Point DNS at the load balancer

```bash
terraform -chdir=digitalocean/environments/small/workload output load_balancer_ip
```

Create an A record, then set `enable_tls = true` and re-apply. Below the large
tier the ACME endpoint defaults to Let's Encrypt **staging**, whose certificates
are untrusted by browsers but carry no meaningful rate limit; switch to
production once a staging certificate has been issued successfully.

## Things that differ from AWS

| | AWS | DigitalOcean |
|---|---|---|
| Secrets | Secrets Manager + External Secrets Operator | Kubernetes Secrets written by Terraform |
| Ingress | AWS Load Balancer Controller + ACM | ingress-nginx + DO Load Balancer + cert-manager |
| Registry | ECR, node role grants pull | GHCR, `imagePullSecrets` for private repos |
| State locking | DynamoDB | **none** |
| Kubernetes auth | `aws eks get-token` | `doctl ... exec-credential` |
| DB credentials | supplied as TF_VAR inputs | **generated by DigitalOcean**, read back from state |
| Storage class | created (`gp3`) | built in (`do-block-storage`) |
| Topology spread | used in staging/production | unavailable — DOKS exposes no zone label |

**Secrets live in Terraform state.** There is no secrets manager to point
External Secrets Operator at, so `modules/kubernetes/app_secrets` writes the
Kubernetes Secrets directly. From medium upward the database passwords are
generated by DigitalOcean and flow cluster layer → state → workload layer →
Secret, so both layers' state files contain credentials. Keep the Spaces bucket
private with versioning on, and restrict who can read it.

**Managed databases have a public endpoint.** Joining the VPC does not close it.
The `digitalocean_database_firewall` rule of type `k8s` naming the cluster UUID
is the actual boundary — `modules/digitalocean/database` always creates one.

**`destroy_all_associated_resources`** is true below the large tier so a destroy
does not leave the load balancer and every PVC behind, still billing. It is
false at large, where deleting volumes would be data loss.
